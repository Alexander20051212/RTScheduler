# ⏱️ Планировщик задач реального времени

Консольное приложение на C# для анализа периодических задач системы реального времени. Программа реализует алгоритмы планирования RMS и EDF, проверяет планируемость системы, вычисляет гиперпериод и формирует диаграммы Ганта.

**Вариант 2 — «Бортовая система»**

## 📌 Возможности

- Загрузка параметров периодических задач из JSON-файла
- Анализ планирования по алгоритму Rate Monotonic Scheduling (RMS)
- Проверка достаточного условия планируемости Liu–Layland
- Анализ времени отклика задач RMS
- Проверка планируемости по алгоритму Earliest Deadline First (EDF)
- Вычисление гиперпериода системы
- Формирование диаграмм Ганта для RMS и EDF
- Сохранение результатов анализа в текстовый отчёт

## 🧮 Реализованные алгоритмы

### Rate Monotonic Scheduling (RMS)

RMS — алгоритм планирования с фиксированными приоритетами. Чем меньше период задачи, тем выше её приоритет.

Дополнительно выполняется анализ времени отклика каждой задачи, позволяющий проверить соблюдение её дедлайна.

### Earliest Deadline First (EDF)

EDF — алгоритм динамического планирования, при котором в каждый момент времени выбирается задача с ближайшим абсолютным дедлайном.

### Диаграммы Ганта

Программа формирует расписания выполнения задач по алгоритмам RMS и EDF на протяжении гиперпериода системы.

## 📋 Исходные параметры варианта

| ID | Название задачи | Время выполнения C | Период T | Дедлайн D |
| 1 | Управление двигателем | 2 | 10 | 10 |
| 2 | Управление тормозной системой | 5 | 20 | 20 |
| 3 | Опрос датчиков | 10 | 50 | 50 |
| 4 | Передача данных по бортовой сети | 20 | 100 | 100 |

## 📊 Результаты работы

Для заданного набора задач получены следующие результаты:

- Суммарная загрузка процессора: **0,850**
- Граница Liu–Layland для четырёх задач: приблизительно **0,757**
- Достаточный тест Liu–Layland: не пройден
- Анализ времени отклика RMS: все задачи укладываются в свои дедлайны
- Проверка загрузки для EDF: пройдена
- Гиперпериод системы: **100**

Непрохождение теста Liu–Layland не означает, что система обязательно непланируема по RMS. Данный тест является достаточным, но не необходимым условием. Поэтому дополнительно выполняется анализ времени отклика задач.

## 🎓 Цель проекта

Изучение алгоритмов планирования периодических задач в системах реального времени, методов оценки загрузки процессора, анализа времени отклика, вычисления гиперпериода и построения расписаний выполнения задач.
